# 架构与状态语义

## 一个进程，一个权威数据库

```text
上传字节 → 确定性解析 → 不可变来源及坐标
                              ↓
编辑者提交业务 IR → 审核决定 → resolve
                              ↓
旧发布包 → diff → impact → compile → verify
                              ↓
                       不可变发布候选
                              ↓
                 独立审批 → CAS 激活 / 回滚
                              ↓
                 固定 release_id 的只读上下文
```

`models.py` 定义输入契约，`engine.py` 负责所有业务门禁和 SQLite 事务，`ingest.py` 只提取证据。`cli.py` 和 `api.py` 使用同一个 Engine；静态控制台只调用 REST。没有第二套前端业务审批逻辑。

## 数据与时态

- 范围 Scope 不可变，描述必需对象、领域断言、排除项和角色 ACL。修改契约须新建范围 ID。
- 来源保存原始字节、SHA-256、解析器标识及片段。来源 ID 绑定范围、字节哈希、解析器和片段；文件显示名不是身份的一部分。重新导入相同内容幂等，ACL 不会被重复导入覆盖。
- 修订 Revision 不可变，含业务对象 ID、类型化字段、声明依赖、证据锚点、权威级别和 `[valid_from, valid_until)`。
- `recorded_at` 由服务器生成；审核/撤销记录追加。`transaction_time` 限制修订及决定的历史可见性；未来记录时间拒绝。时间均转为固定微秒精度 UTC。
- 审核从未发生的修订为草稿，不参与权威竞争。已决定的候选按 `(authority, valid_from)` 排序；同级同生效时间多个候选为 CONFLICTED，最高候选被撤销则为 REVOKED，不静默回退。
- 历史查询始终应用**当前**来源权限和撤销策略。历史记录时间不提供恢复旧权限的途径。范围和来源策略本身不是完整双时态模型。

## 五个计算原语

`resolve` 返回当前可见对象、UNKNOWN/CONFLICTED/REVOKED 问题及范围排除项。有效期、权威与权限均可能使对象缺失。缺失必需对象阻止发布。

`diff` 按对象字段进行确定性比较，区分布尔值、整数和浮点表示，识别阈值增减。依赖、ACL、来源锚点、生效区间等变化也被报告；只有修订 ID 改变而语义字段不变时，不制造业务变更。

`impact` 的 forward 是依赖者传播，reverse 是上游依赖闭包。构建使用旧/新边集合并集，避免删除一条关系后丢失影响。广度优先搜索记录一条最短解释路径；环会终止，不意味着业务上的循环依赖已被证明正确。显式缺失对象形成 frontier。

`compile` 嵌入 `build`，将受影响对象生成审核任务，并执行范围声明的**全部**检查。预览版不使用增量测试裁剪，避免被未通过的基线绕过。`critical` 保留在 IR 中，当前不改变门禁：任何失败检查都会阻止发布。

`verify` 支持 `eq/gte/lte/contains/exists`，可引用另一个对象的字段。数值比较只接受数值，不将布尔值视为数字；等值/列表包含按 JSON 表示比较。字段/引用缺失、类型不适合、断言失败均不通过。没有检查时为 NEEDS_REVIEW，即使人工批准也不能激活；须建立有检查的范围。

## 不可变发布包与运行时

发布 ID 是规范 JSON 的 SHA-256，覆盖范围、状态、基线、差分、影响、编译计划、构建报告和算法版本。记录时间参与内容，所以在不同记录时间构建可以产生不同 ID；相同输入快照产生相同 ID。

`evidence_objects` 保存本次状态与基线状态的修订，保护差分中的历史证据。读取发布包需要对全部这些对象和来源拥有权限，权限不满足时整包拒绝，避免删改前数据泄漏。这也意味着旧来源撤权后，含其历史差分的包不可读取；可撤销失效活动包，重新建立不含旧基线的新候选。

发布元数据中的审核者、永久撤销位、活动指针及激活日志可更新；包正文不更新。审批者 ID 必须不同于构建者。审批时检查包声明的业务时间，激活和消费时检查当前时间。通过未来场景构建不能提前激活未来规程。

激活在 `BEGIN IMMEDIATE` 事务内比较 `expected_active`，修改活动指针并追加日志，竞争者获得 409。回滚目标必须已激活过、仍批准且可用。已固定的旧包不因活动指针切换自动失效；若旧包确实不应再使用，必须撤销。

运行时上下文必须指定发布 ID 和 1–100 个对象 ID；返回它们的依赖闭包。包须 PASS、独立批准且曾激活，当前来源 ACL、来源哈希、修订审核、发布撤销及有效期全部重新检查。没有执行工具、设备命令或可写 Agent 权限。

## 有意保留的边界

SQLite 单租户适合本地试用；构建和审计读取使用写事务串行化，不面向大规模高并发。业务图完全来自审核后的依赖声明，无法证明未声明知识的完整性。文本抽取保留确定坐标，但不恢复完整排版语义；未覆盖 DOCX 页眉/嵌套表、PPTX 分组/备注、图像 OCR。XLSX 公式保存原式，不计算、不外联。

当前模式为 `filewise/v1alpha1`，没有旧草稿数据库迁移器。此仓库首次可运行版本应使用新数据库；上线前需要专门设计迁移与备份验证。zvec-grep 和模型提案尚未接入，扩展边界详见评估文档。

## 文件产品层

`projects.py` 将注册目录或完整上传集映射到内核来源与修订；所有原文件字节均保存，未提取的格式明确标识。每个候选快照包含 manifest、位置变更报告和内容寻址的内核发布包。`changes.py` 比较 JSON Pointer、Excel/CSV 坐标以及对齐的文本片段，给出数值、公式、约束用语等规则提示。格式/元数据变化可能只有字节差异，不会假装识别出语义。相同文件内容与契约复用修订。

候选文件集合由 `Engine.build(..., revision_ids=...)` 明确固定，便于在审核之前运行检查。这个内部入口不改变运行时审批要求：构建 PASS、全部修订批准、独立发布审批、曾经激活及当前证据可用缺一不可。项目审批会批准当前集合的修订后批准发布；若中途失败，发布仍不可使用。

项目总是有文件集完整性检查。未配置业务检查时，报告明确写 `file_integrity_only`，PASS 仅代表文件集检查；人工审批不产生额外自动语义保证。有检查时，文件字段来自声明的 JSON Pointer、单元格或片段坐标；缺失/类型不匹配导致 BLOCKED。项目依赖/检查契约在创建时固定，改变契约须创建新的项目 ID；尚未提供原位修改或跨项目合并。

命名提交使用 `project_commits` 记录快照引用、父提交、说明、作者和时间；内容哈希校验元数据和线性父链，写事务检查 expected_parent 后追加，同时写入审计。已有快照保持不变，不批量转换成提交。保存快照、记录提交、审批发布是分开的操作。比较复用原有定位差分与声明依赖传播；提交本身不改变原件或运行时读取资格。

项目快照 manifest 与不可变发布对象逐字段核对，报告另有校验和。报告校验和与数据库审计都用于检测损坏，不是外部签名。源字节和解析片段由发布证据绑定。批准快照不直接修改原文件；上传是完整版本替换，删除仍保存在历史中。

Agent 通过 `agent open/ls/read/search` 请求网关，HTTP 凭据由服务端固定为 `audience=agent`；此类凭据不能访问内核/操作员的草稿证据入口。会话绑定 Actor 与 release_id，读取返回原文/提取位置、原字节的 base64 和带哈希的审计凭据。凭据摘要不是数字签名。

上传项目使用不可变版本；本地目录项目每次运行时读取还扫描目录，与所选版本的所有文件哈希比对。工作文件改变即返回 STALE。启用关注后，稳定的保存变化自动触发候选；也可手动同步。扫描不是操作系统级原子文件系统快照，返回内容始终取自不可变来源，不混读最新字节。

主界面为文件工作台，旧内核控制台保留在 `/admin`。`showcase` 创建专用临时数据库、合成文件和演示身份，仅监听回环地址；普通 `serve` 不启用演示端点。`agent.py` 不创建本地数据库；可信操作员可用 macOS `project launch` 对新 Agent 进程施加文件访问限制。详见 [Agent 使用说明](agent.md)。

`connections.py` 管理项目钩子、同一 Agent 任务的审核副本和连接状态；`middleware.py` 统一捕获候选、检查原件基线、独立审核后的写回与故障恢复。原生文件工具改写路径；Shell 钩子准备一个等待进程，宿主获准执行工具后通过副本内的文件信号启动指定命令。受控进程独立应用 Filewise 的 macOS 规则，避免某些宿主沙箱拒绝嵌套 sandbox-exec；工具侧只传信号和读取输出，不访问数据库。输出描述符预先打开，命令参数保留在进程中，完成后由 PostToolUse（Claude 还包括 PostToolUseFailure）捕获候选。未启动的准备进程 10 分钟后退出；已启动时监测工具进程，工具退出会终止受控命令进程组。文件信号不是身份凭据或远程执行接口。
