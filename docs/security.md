# 安全边界

## 身份与权限

HTTP Bearer 令牌映射到服务端 Actor；角色为 reader/editor/reviewer/publisher，没有隐含角色继承。ACL 是角色集合的 OR 匹配，同时检查范围、对象及证据来源。默认上传 ACL 为上传者的角色集合，需要共享时显式声明。

HTTP 在解析业务请求正文前认证，客户端不能通过请求体或角色头自行提升权限。所有 `/api/*` 路由，包括 OpenAPI，均需令牌。普通服务只有静态页面与 `/health` 匿名可见；专用 `showcase` 的 `/demo` 公开合成实例的演示身份，普通服务该端点返回 404。令牌文件只在启动时读取，修改/轮换后须重启；生成文件使用独占创建、权限 0600，不覆盖已有文件。

这是静态本地身份机制，不提供 SSO、MFA、多租户、按用户细粒度 ACL 或组织审批签名。令牌配置者必须保证 actor ID 对应真实独立身份；CLI/Python 调用者以及数据库文件管理员均处在可信边界内。发布构建者不能以同一 ID 批准自己；本版本不强制分离发布审批者与激活者，也不强制分离修订作者与修订审核者。

## 证据与发布

输入文件只用于提取数据。内核上传文件名去除目录；项目上传保留经验证的项目相对路径（拒绝绝对路径、父目录、反斜线及重复路径），只保存到 SQLite，不据此写服务器磁盘。普通 serve API 不接受服务器任意路径。仅绑定回环地址的 start/follow 开启本机设置接口，由已认证的编辑者显式选择目录和安装项目 Agent 接入。输入模型拒绝额外字段、无时区时间、无效 ID 和空 ACL。限制单文件 10 MiB、HTTP 正文 11 MiB、20,000 个非空片段和 2,000,000 个文本字符；Office 压缩包展开体积最多 50 MiB，最多 10,000 个成员，PDF 最多 500 页。

这些限制不能完全隔离恶意解析器输入的 CPU/内存消耗。当前同步 PDF/Office 解析适用于本地可信或预先检查的文档；面对不可信公网上传，需要独立进程/容器的 CPU、内存、超时限制和代理层请求速率限制。宏、公式、外部链接和文档内指令均不执行。

原文坐标与 quote 子串匹配仅证明引用存在，不证明业务字段可由该引用推出。编辑与领域审核负责语义正确性。PASS 限于 Scope 声明的断言，不能被解释为通用业务安全证明。

历史查询采用当前 ACL；发布包读取还校验差分中历史对象的证据。撤权/来源撤销不会删改包正文，但会立即阻止未来的可信上下文读取。已发给外部消费者的数据无法收回，消费者应避免无限期缓存并在每次使用时重新获取。

## 浏览器与部署

控制台无第三方脚本、字体、CDN 或模型调用；动态内容使用 textContent。工作台令牌保存在当前标签页的 sessionStorage，刷新页面可继续使用；不写 localStorage 或 cookie。start 的本机登录链接在 URL fragment 中携带令牌，页面读取后立即用 history.replaceState 清除，不作为 HTTP 请求路径或查询参数发送。关闭标签页结束本次浏览器会话；不要分享该登录链接。响应使用 no-store、nosniff 及 CSP；服务端不开放 CORS。HTTP 默认仅监听回环地址。

远程部署应由反向代理提供 HTTPS、受控网络入口和请求限制。不要暴露数据库或令牌文件，不要将本地管理员 CLI 当成远程授权协议。不支持直接公网多租户服务。

SQLite 数据未加密；使用操作系统磁盘保护、文件权限和离线备份。WAL 模式备份应使用 SQLite backup API，或关闭所有写入连接后复制完整数据库状态；不要在线只复制主 `.db` 文件。

审计链可发现普通篡改和链中不一致，但不是数字签名。拥有数据库写权限的人可重算整条链，尾部截断在没有外部锚定 head 时也无法单独检测。需要抗管理员篡改时将审计 head/日志锚定到受独立控制的存储。

## 仓库与外发

仓库只包含实现、文档、合成样例和测试。`.filewise`、数据库、令牌和本地连续工作记录不进入 Git；sdist 与 Docker 均用白名单。只在 Filewise 子目录运行 Git，禁止在业务材料父目录初始化、添加或推送。检索扩展或远程模型需要独立的授权证据投影和外发配置；当前版本没有这些网络调用。

## 文件项目与受限 Agent

注册目录须由可信本地操作员完成。同步跳过符号链接、非普通文件和明确排除项，逐级使用 O_NOFOLLOW 打开；排除清单包含 `.git`、`.filewise`、`.venv`、`.env*`、常见令牌/密钥路径。排除规则不是通用秘密检测，操作员仍须选择正确的项目边界。每项目最多 1,000 文件、50 MiB，单文件 10 MiB。网页完整上传集仍受 11 MiB HTTP 限制。

`audience=agent` 的令牌只能读项目摘要及使用会话 API，不能进入任何操作员内核端点。会话 ID 不能代替认证，且绑定 Actor。每次读取重验来源和发布门禁，目录项目还核对工作文件哈希。读取回执含内容哈希和审计记录，不是数字签名。来源文本是数据，不授权工具执行。

工作台下载原文件走受权限控制的接口；预览用 textContent，不渲染文件中的 HTML 或执行脚本。原件下载由用户自行决定如何打开。

macOS `project launch` 的文件读写限制仅施加到新启动的 Agent 及其后代，保护注册目录、当前 SQLite 文件及日志、令牌文件；Agent 只获得 reader/agent 凭据。它不是整个主机的隔离，也不约束另一个外部 MCP/浏览器/终端代理进程。直接启动已有权限的 Codex 并贴入一句使用说明不构成强制边界。[详细操作与限制](agent.md)。

## 本机原生接入

Codex/Claude 项目 hooks 和 Pi 项目扩展只在显式选定目录安装，原配置先备份到私有 SQLite，再做带内容冲突检查的替换。断开保留其他设置；配置预览只返回 Filewise 新增项。所有安装/自检接口要求操作员身份，Agent 凭据被拒绝。配置文件与审核副本默认不进入文件快照。

钩子参与原生工具执行，不能作为整个宿主进程的强制边界；关闭钩子、其他插件修改参数、外部 MCP 或宿主自身失败策略均可能绕开这层。Filewise 的受控 Shell 只允许在副本内写入并拒绝访问原目录及私有状态。接入保持原有配置，但 Codex updatedInput 协议要求该工具的 permissionDecision=allow；这不批准候选写回，也不代表所有工具都受控。具体范围见 [中间件说明](middleware.md)。
